# 로그인 만료 5일 전부터 일일 Telegram 알림

- 날짜: 2026-09-12
- 상태: 채택, 사용자 명시 요청.
- 배경: 기존 운영 정책은 만료시각으로 로그아웃을 단정하지 않도록 실제 로그인 해제·복구만 알렸다. 사용자가 만료 5일 전부터 매일 한 번 사전 경고를 요청했다. 이 결정은 기존 ISSUE_LOG의 “표시 만료시각만으로 선제 경고하지 않는다”는 알림 정책만 대체한다.

## 기존 구현과 소유권

기존 구현은 **일부 있음**이다. `tools/spacecloud-watch.mjs`의 세션 점검, 쿠키 진단, `notifySessionStateChanges`, `notifyOnStateChange`와 영구 `notify-state.json`을 재사용한다. 빠진 책임은 현재 세션의 만료 예고 대상 판정과 일일 묶음 메시지 구성뿐이므로 같은 감시기 안에 두 보조 함수를 둔다. DB 스키마·예약 큐·상태값·별도 예약 실행기는 추가하지 않는다.

## 결정

- `ready`인 실제 화면 검사 후 관찰한 주 인증 쿠키의 명시적 만료일만 사용한다. 과거 쿠키에서 이어받은 진단 최상위 만료일, 만료일 없는 세션 쿠키, 쿠키 조회 실패는 예측 근거로 사용하지 않는다.
- 한국 날짜 기준 D-5부터 만료 당일까지 첫 대상 점검에서 네이버·스페이스클라우드를 한 메시지로 묶어 하루 한 번 보낸다. 정확한 만료시각부터 사전 경고 대상에서 빠진다. 그날 메시지 이후 새로 대상이 된 플랫폼은 다음 날 포함한다.
- 메시지는 “기록된 만료일”과 남은 날짜를 알린다. 만료일은 실제 인증 유효성을 보장하지 않는다. 서버가 일찍 인증을 거절하면 기존 로그인 필요 알림을 즉시 보낸다.
- 같은 영구 알림 파일의 별도 키 `system:session-expiry`에 성공한 한국 날짜를 저장한다. 플랫폼/쿠키 변경·캐시된 점검·재시작으로 같은 날 다시 보내지 않는다. 실패한 발송은 성공으로 기록하지 않으며 최소 5분 뒤 재시도한다. 미리보기는 발송 기록을 소비하지 않는다.
- 재로그인으로 만료일이 5일 밖으로 연장되면 경고가 멈추고 새 날짜에 맞춰 재개한다. 이미 로그아웃했거나 검사에 실패한 세션은 기존 장애·복구 경로가 담당한다.

## 보호와 롤백

인증/2차 인증 우회 금지, 장애 플랫폼의 작업 시도 횟수 보존, 예약·SMS 원장과 세션 알림 상태의 분리, 실제 화면 검사만 정상으로 인정하는 원칙을 유지한다. 외부 부작용은 요청받은 Telegram 경고뿐이다. 새 알림 키는 기존 장애 키와 충돌하지 않는다. 롤백은 감시기 파일을 이전 버전으로 되돌리면 되며 해당 키는 남겨도 구버전이 무시한다. 기존 알림 상태를 삭제하거나 초기화하지 않는다.

## 검증

기존 NOW-mode 자체검사를 확장했다. D-6/D-5 한국 자정 경계, D-4부터 당일·만료 직후, 현재/구형 진단·미상 만료일, 로그인 장애, 갱신, 두 플랫폼 묶음, 반복·캐시 검사, 파일에 저장한 날짜로 중복 억제, 다음 날 재개, 발송 실패/재시도, 미리보기·비활성화를 확인한다. Telegram 전송은 모의 응답으로 검증하며 실제 고객 문자나 외부 예약 작업을 실행하지 않는다.
