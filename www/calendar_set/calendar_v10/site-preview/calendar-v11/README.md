# 홈페이지 연결 전용 캘린더 v11

2026-10-08에 v10 소스(저장소 기준 521ec27)에서 복사한 독립 UI다. 원본 v10 파일을 편집하지 않는다. `site-preview/build.py`로 소개 페이지를 재빌드해도 이 파일들은 덮어쓰지 않는다.

- `index.html`: 기존 미리보기 캘린더에서 예약 버튼, 안내 메뉴/팝업과 그 핸들러를 제거했다.
- `calendar-v11-server-cache.js`: v10 런타임 복사본. 공개 캐시·시간/룸 필터를 유지하며, v11 색상과 공통 이벤트 표시를 소유한다.
- `server-calendar-sync.js`: v10 로더 복사본. 데이터 주소만 기존 운영 공개 캐시의 절대 주소로 연결했다.
- `style.css`: 원래 레이아웃 위에 v11의 밝은 배경·크기·줄바꿈 규칙을 적용한다. `roomConfigs`가 룸 색상의 단일 기준이다.
- `offcanvas-navbar.css`, `swipeCalendar.js`, `browser-guards.js`: 원래 동작을 보존하는 복사본이다.
- `embed.js`: 이미지/링크의 기본 드래그를 막는다. 일정표의 날짜 스와이프는 유지한다.

새로운 예약 처리·DB 원장·동기화 작업은 없다. 원본 v10과 v11은 동일한 공개 예약 데이터를 읽으며, 외부 예약 버튼은 부모 사이트에만 존재한다.

## 모바일 가독성 수정

19px 기본 글꼴과 데스크톱에만 있던 줄바꿈 방지가 모바일의 좁은 5개 룸 칸에서 세로 글자열을 만들었다.
기존 `getRoomEventHtml()`을 주/월·단일 룸 표시에서 재사용하고, 9~10px 글자와 한 줄 말줄임으로 표시한다.
전체 룸 주간 보기에서는 색상/룸 글자를 우선하며, 룸 선택과 기존 상세 팝업에서 정확한 시간을 읽는다.
시간 계산·조회 범위·원장·외부 예약 처리에는 손대지 않는다.
검증은 실제 공개 캐시를 사용한 주간/월간, 룸 필터, 상세 팝업, 모바일/PC 색상과 가로 넘침에 한정한다.

PC에서는 제거된 v10 사이드바의 빈 폭을 캘린더에 돌려주고, 단일 룸 상세 패널을 열면 40% 폭으로 시간을 읽을 공간을 확보한다.

## 2026-10-08 요일·날짜 머리글 가림 수정

- 증상 → 판정 로직 → 화면 부작용 → 외부 결과: 공개 `/schedule/` iframe에서 요일·날짜가 안 보임 → `getWeekColumnHeaderHtml()`과 주/월 `columnHeaderHtml`은 올바른 날짜를 생성함 → `4091dd0`의 `#calendarAll .swiper-container { top:0!important }`가 슬라이드를 월 제목 아래가 아닌 같은 시작점에 놓아 높은 z-index의 제목이 글자를 가림 → 예약 데이터 누락이 아닌 화면 겹침이며 원장/외부 예약 변경은 없음.
- 기존 구현 **있음**: `calendar-v11-server-cache.js`의 공통 머리글 생성과 `style.css`의 툴바 배치를 재사용한다. 중복 날짜 DOM·상태·함수를 추가하지 않는다. 기존 수정의 보호 목적은 하단 룸/날짜 버튼을 정렬하고 그 높이만큼 일정표 공간을 확보하는 것이었다.
- 변경: 기존 높이 계산에 월 제목의 34px 공간도 포함한다. `--calendar-title-height`는 v11 스타일에서 제목 높이와 슬라이드 시작 위치를 함께 소유한다. CSS URL 버전을 갱신해 구 캐시의 `top:0`을 피한다.
- 유지 조건: 하단 개별 버튼 높이, 전체/개별 선택, 주/월 공통 머리글, 오늘 표시, 00~24시 표시, 이미지 드래그 방지, 공개 캐시 읽기 및 원본 v10 보존.
- 검증: 실제 공개 캐시로 모바일 390px의 주간·다음 주·이전 주·월간·주간 복귀·A홀·전체·오늘, 320px 주간, PC 주간·A홀 상세·월간 총 12개 화면 상태를 검사했다. 7개 요일의 실제 글자 영역이 제목 아래/시간표 위에 있고 마지막 23시 행도 하단 버튼에 가려지지 않음을 확인했다. 월간은 요일 7개와 날짜 셀 42개를 확인했다. 기존 `ops/site_preview_swipe_selftest.cjs` 71개 검사 통과.
- 제외: 예약 생성/취소·동기화·DB·외부 플랫폼 쓰기는 변경 경로 밖이므로 실행하지 않는다. UI만 수정한 검증을 위해 운영 예약을 생성하지 않는다. 운영 반영은 `index.html`/`style.css` 두 파일만 백업 후 교체하며, 두 파일을 함께 복원하면 롤백된다.
- 운영 1차 확인: localhost의 브라우저 확대율 90%와 운영 도메인의 100%가 달라, 기존 `2.8vh` 시간 행 높이와 경계선 누적이 운영에서 마지막 행을 약 10px 자르는 것을 발견했다. 머리글 복구는 정상이었다. 후속 사용자 요청으로 하단 로고/상호 줄을 제거하고 하단 전체 높이를 모바일 128→96px, PC 86→54px로 줄여 시간표 공간을 확보했다. 시간 행 자체는 축소하지 않아 24개 칸의 같은 높이를 유지한다. 원본 시간 행 규칙은 24시간을 한 화면에 맞추려는 목적으로 v10에서 복사된 구현이다.
